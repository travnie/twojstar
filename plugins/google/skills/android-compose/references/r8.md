# R8 / keep-rule analysis

Identify release variants, AGP/R8 versions, minification/resource shrinking, optimize rules, merged configuration and library consumer rules. Review legacy fullMode opt-outs. Do not upgrade AGP merely to run an audit.

Choose the strongest available evidence:
Find the AGP and R8 versions in `build.gradle(.kts)`, `settings.gradle(.kts)` (a pinned R8 there replaces AGP's bundled one), `gradle.properties` and the catalog; find the module and an R8-enabled variant (usually `:app` / `release`).
- **AGP ≥ 9.3:** run `:<module>:analyze<Variant>R8Config`; report lands in `<module>/build/reports/r8/*.pb`. AGP 9.3 also brings the simplified `optimization {}` DSL — worth suggesting on older AGP, not forcing.
- **AGP < 9.3:** upstream temporarily pins R8 ≥ 9.4.34 in `settings.gradle(.kts)` to get the same report from a release build. That edits the project — ask first, back the file up, restore it after.
- Upstream now ships the helpers (`performance/r8-analyzer/scripts/convert_pb_to_json.py`, `analyze.py`, needs `protobuf>=6.33.4`) and `references/INSPECT-RULES.md` for redundant-rule patterns. Fetch them from the pinned commit and read before running. Both paths need Gradle — on a dev machine or via a CI job, not in chat.
- Otherwise inspect merged rules, consumer rules and reflection paths heuristically. Clearly label heuristic findings and do not invent scores or byte savings.

Prioritize package-wide `-keep ... ** { *; }`, inverted matches, global optimization disabling and broad suppression. Before removing a rule, prove the selected library version supplies the necessary consumer rules and that app reflection/JNI/serialization still works. Narrow exact classes/members and add allow-optimization/obfuscation/shrinking only where their behavior is safe. Do not treat `-keep class X` as equivalent to `-keepnames`; reason from actual R8 semantics.

For an audit, report rule location, reason, proposed change and evidence/confidence. Change files when implementation is requested, preserving one coherent patch. Validate the minified release build plus critical reflection, serialization, native calls, startup and navigation paths. Debug-build success is insufficient. Measure comparable release artifacts before/after if reporting size changes; distinguish APK/AAB/download size. Protect and retain matching mapping files.

Docs: https://developer.android.com/topic/performance/app-optimization and https://r8.googlesource.com/r8 .
